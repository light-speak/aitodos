# ADR-0006：项目固定端口与显式打开浏览器

- 日期：2026-08-19
- 状态：Accepted
- 修正：ADR-0002 的随机端口默认约束和 ADR-0005 的自动打开浏览器行为

## 背景

随机端口会让同一项目每次重启后 URL 改变，已打开的浏览器标签页无法继续使用。`ats start` 自动打开新页面也会在频繁重启时产生重复标签页。项目仍需支持并行运行，因此不能为所有项目强制使用同一个全局端口。

## 决策

1. Daemon 只监听 `127.0.0.1`，不扩大网络暴露范围。
2. `.ats/local.toml` 增加 `server.port`；`0` 表示由操作系统分配随机端口，`1` 到 `65535` 表示当前项目的固定端口。
3. 新项目默认写入 `server.port = 0`。旧项目缺少 `[server]` 时按 `0` 处理，不要求配置迁移。
4. `ats start --port PORT` 可以单次覆盖 `server.port`，但不修改配置文件。
5. 固定端口被占用时启动失败并返回监听错误，不静默回退到随机端口。
6. `ats start` 始终在前台运行且不自动打开浏览器。用户复制启动输出中的 URL，或显式运行 `ats open`。
7. 删除 `--no-open`；它在默认不打开浏览器后不再表达有效差异。
8. 多个项目并行运行时，由用户为各项目选择不同固定端口，或让其中部分项目继续使用随机端口。

长期固定端口示例：

```toml
[server]
port = 6170
```

## 后果

- 同一项目重启后可以复用原浏览器标签页和书签。
- 启动服务不再产生非预期浏览器窗口。
- `.ats/local.toml` 已被项目 `.ats/.gitignore` 忽略，因此不同机器可以选择不同端口。
- 固定端口引入端口冲突的可能；启动错误会保留操作系统提供的占用信息，用户需修改配置或释放端口。

## 被否决的方案

### 所有项目共用一个默认固定端口

配置最少，但不同项目无法同时运行，也与每项目独立 Daemon 的边界冲突。

### 每次启动自动寻找固定端口附近的空闲端口

看似减少冲突，但 URL 仍会变化，破坏固定端口的可预测性。

### 保留默认自动打开浏览器

用户可以通过 `ats open` 显式获得相同行为；默认自动打开会在开发重启期间不断产生新标签页。
