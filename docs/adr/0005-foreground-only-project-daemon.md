# ADR-0005：项目 Daemon 仅允许前台运行

- 日期：2026-08-19
- 状态：Accepted
- 修正：ADR-0002 的后台启动与 detached child 进程设计
- 后续修正：浏览器打开方式和端口配置由 ADR-0006 修正；前台生命周期决策保持有效

## 背景

后台启动会让服务生命周期脱离用户当前终端，增加“终端已经关闭但项目仍在运行”的认知成本，也需要内部 `_serve` 命令、子进程分离、后台日志和额外的启动对账逻辑。AiTodos 当前是本地优先、单用户工具，明确可见的进程生命周期更重要。

## 决策

1. `ats start` 默认且只能在前台运行，不再接受 `--foreground`。
2. 启动终端必须保持打开；`Ctrl+C`、终端关闭或父进程收到终止信号时，项目 Daemon 随之退出。
3. `--no-open` 只控制是否自动打开浏览器，不改变进程生命周期。该参数已由 ADR-0006 删除，`ats start` 现在始终不自动打开浏览器。
4. 删除 detached child、后台 `Launch` 和内部 `_serve` 命令，不保留隐藏后台入口。
5. `ats status`、`ats open` 和 `ats stop` 保留，允许用户从另一个终端观察、打开或停止正在前台运行的项目。
6. 每项目独立 SQLite、loopback 监听、lock 和 runtime metadata 等 ADR-0002 决策保持不变；随机端口由 ADR-0006 扩展为项目本机可配置端口。

## 后果

- 服务是否运行与一个可见终端一一对应，开发和排错更直接。
- stdout/stderr 直接留在启动终端，不再维护 Daemon 后台日志。
- 用户需要保持终端开启；关闭终端即停止 Web UI、Scheduler 和后续 Runner 调度。
- 同一项目重复执行 `ats start` 会因项目锁而失败，不会复用或创建第二个进程。

## 被否决的方案

### 同时保留前台和后台模式

模式更多，但生命周期、日志位置和停止语义不统一，也保留了误启动后台服务的可能。

### 默认前台但保留隐藏后台命令

仍然存在无法从公开 CLI 解释和保证的运行方式，不符合“终端一定要开着”的产品约束。
